# 试卷处理标准流程

确认日期：2026-11-13。适用目录：`D:\Tools\exam-print`。
本文件是后续处理、维护程序和交付结果的默认标准。用户明确指定其他排版时，以当次指令为准。

## 1. 默认结果

默认输出 **A4竖版、双面后左右拼接，得到A3展开效果**。
四页试卷的PDF实际页码必须为 **1 → 4 → 2 → 3**。
这里的页码指试卷印刷的真实页码，不是导入照片的序号或文件名顺序。

| 纸张 | 正面 | 背面 |
|---|---|---|
| 第一张A4 | 第1页 | 第4页 |
| 第二张A4 | 第2页 | 第3页 |

正面左右拼接为 `1｜2`，整体翻面后为 `3｜4`。
书本页码45–48对应输出 `45 → 48 → 46 → 47`。
真正的A3整张输出只在用户明确要求时使用；普通顺排是正面 `1｜2`、背面 `3｜4`。
不要将A4拼接页序误改成A3对折成册的拼版。

## 2. 输入与启动

1. 默认读取 `待处理试卷` 文件夹，不要求每次输入路径。
2. 双击 `处理试卷.bat` 启动；也保留拖入文件和命令行入口。
3. 支持照片和扫描PDF；同批两种来源分别处理，不直接混排。
4. 一次只放一套照片时无需重命名，先识别真实页码，再排序。
5. 同时处理多套照片时，用 `a1/a2`、`b1/b2` 等字母前缀明确分套。程序当前不能承诺从任意混放照片中可靠识别试卷归属。
6. 每个PDF独立分析；一本PDF中发现多套完整四页试卷时，分别输出。
7. 核验通过后，默认待处理目录中的原文件自动移到“已处理”；保留原名，同名加序号。失败输入留在原处；从外部拖入的文件只处理，不搬动。

## 3. 图像整理

1. 读取EXIF方向，校正横竖和倒拍方向。
2. 对左右两页照片寻找中间空白带，拆成单页。
3. 识别页脚真实页码和总页数；核对同一套是否完整、重复或混卷。
4. 照片页码不完整时显示缩略图核对窗口，填写实际页码后再输出。
5. PDF页码或分套不明确时停止并说明，不通过文件名或题目位置强行猜测。
6. 保留题目、拼音、细线、田字格、插图、答题空白和页码。等比缩放、白底居中，不拉伸，不裁掉内容。
7. 默认不进行OCR文字重排、不去答案、不强制黑白化，不擅自改变试题。
8. 页脚识别只用于排序；OCR识别结果不能替换原始印刷内容。

## 4. PDF处理

- 照片：Pillow处理，保留原图；生成高质量打印PDF。
- 扫描PDF：pypdf负责裁切、缩放和拼版；尽量直接保留原嵌入图像，避免重新编码JPEG。
- PDFium用于需要时的分析和最终渲染验证。
- 当前自动PDF分套只针对四个连续页码；遇到其他结构应说明并另行处理。
- PDF页面旋转标记、拍摄透视、明显倾斜不属于当前脚本完整自动处理能力，不能宣称已自动修好。
- 可选开源工具：ScanTailor Advanced用于精细分割、纠偏、内容区域和边距调整；OCRmyPDF用于扫描文字层。是否采用取决于具体输入，不默认安装或重度处理全部试卷。

## 5. 输出前必须验证

仅“脚本执行成功”不算验证完成。

1. 打开或渲染最终PDF，逐面检查方向、切缝、内容边缘、图表、答题区域和页脚。
2. 确认每套四页，PDF实际页序为 `1、4、2、3`；书本页码使用对应顺序。
3. 从生成PDF的实际渲染页脚再次读取页码，优先300dpi；不能只信生成日志。
4. 确认纸张实际尺寸为 **210 × 297 mm**，竖向；真正A3模式才是 **420 × 297 mm**，横向。
5. 扫描PDF保留原图的流程，对比源文件与结果中的嵌入图像数据，确认没有意外重采样或重新压缩。
6. 发现方向、缺页、错序、截字等问题必须修复后重验。无法确定时明确指出待核对部分，不能声称验证通过。
7. 区分“电子PDF已验证”和“打印机实际试印”；没有走纸测试时不得宣称已经实物打印验证。

## 6. 固定交付

每次由助手处理并交付时，提供：

- 每套独立的A4打印PDF。
- 每套打印说明，记录来源、真实页码、输出页序和打印设置。
- 本批拼接效果预览，按正面 `1｜2`、背面 `3｜4` 展示；不要把预览图当作打印文件。
- 本批核验结果，简要记录页序、页数、方向、尺寸以及未解决的输入质量限制。
- 本批打印文件压缩包，方便一次保存。

本机本次正式文件存放在 `output/最新结果`；上一批自动移到 `output/历史结果`，全失败或空运行不替换上次最新结果。聊天需要可下载链接时，将相应交付副本放入当前聊天的 `outputs`，使用绝对路径链接。
旧版错误结果需单独备份并标明勿打印，避免与已验证文件混淆；保留原文件便于追溯。

当前双击脚本已自动生成分套PDF、打印说明、实际渲染页脚核验结果、核验预览、整批拼接预览与压缩包；自动归档通过核验的输入并打开最新结果。自动检查覆盖页序、页数、尺寸、方向；题目边缘完整性与视觉质量仍需要查看预览，助手交付时必须另做逐面视觉核对。

## 7. 固定打印设置

**A4、竖向、每张1页、双面长边翻转、适合可打印区域。**
PDF已经排好页序，不要在打印软件里再次选择小册子、每张2页或重排页码。
每套是两张A4纸。首次使用某台打印机时先试印一套，确认翻面方向后再批量打印。

## 8. 日常操作速记

放入照片或PDF → 双击处理试卷 → 必要时核对本套页码 → 查看output/最新结果 → 按固定打印设置打印。
后续用户说“按之前的流程处理”，直接遵循本文件，无需重复询问默认纸张和页序。

## 10. 自动命名、归档和本地运行

- 自动识别标题、年级和科目，给打印PDF命名，例如“一年级语文_期中测试卷”。未识别的字段不猜测；无法识别科目时用试卷加日期，重名加序号。
- 一次一套的照片无需改名；多套同时处理仍用a/b等前缀指定归属，避免同页码不同试卷混排。
- 核验前记录输入SHA-256，核验后确认原文件未被替换，再归档到已处理；归档记录保存原路径、目标路径和结果路径。
- 原文件重名不会覆盖，组内搬动失败会尝试恢复已搬动文件；失败后明确提示。
- 本次结果固定在output/最新结果。通过核验的本批结果发布后，上一批转入历史结果；失败草稿与核验通过PDF分开标识。
- app是源码目录；tools是工程内开源工具与离线依赖；.venv是本地运行环境。运行不读取Codex目录，不依赖在线API。
- 运行所需Python依赖已固定版本；安装脚本优先离线包。Poppler缺失时从上游GitHub发行包恢复。
- Git只跟踪代码、启动脚本、文档、测试和依赖/工具来源信息，不跟踪个人试卷、打印结果和生成的运行环境。
